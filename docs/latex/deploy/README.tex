\hypertarget{deploying-a-sovereign-satspath-authority}{%
\section{Deploying a Sovereign SatsPath
Authority}\label{deploying-a-sovereign-satspath-authority}}

This guide explains how to deploy \texttt{satspathd} as a
\textbf{sovereign single-domain authority} or a \textbf{multi-tenant
hosted provider}.

SatsPath allows \texttt{name@yourdomain.com} to be realistically
deployable without hiding the underlying security model.

\hypertarget{onboarding-workflow}{%
\subsection{Onboarding Workflow}\label{onboarding-workflow}}

\hypertarget{initialize-operator-and-dns-records}{%
\subsubsection{1. Initialize Operator and DNS
Records}\label{initialize-operator-and-dns-records}}

Run the CLI operator tool to generate your operator keys and output the
required DNS records:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{satspath}\NormalTok{ server init yourdomain.com}
\end{Highlighting}
\end{Shaded}

Add the printed \texttt{TXT} records to your DNS provider (e.g.,
Cloudflare, Route53, Bind).

\hypertarget{verify-dns-and-trust-quorum}{%
\subsubsection{2. Verify DNS and Trust
Quorum}\label{verify-dns-and-trust-quorum}}

Once DNS records propagate, verify the DNSSEC chain, operator key, and
transparency log:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{satspath}\NormalTok{ server check yourdomain.com}
\end{Highlighting}
\end{Shaded}

\hypertarget{deploy-with-docker-compose}{%
\subsubsection{3. Deploy with Docker
Compose}\label{deploy-with-docker-compose}}

We provide a reproducible deployment via Docker Compose. Private user
keys \textbf{never} reside on the server and are generated locally by
users.

Edit \texttt{docker-compose.yml} to set
\texttt{SATSPATH\_AUTHORITY\_DOMAIN} and deploy:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{docker{-}compose}\NormalTok{ up }\AttributeTok{{-}d}
\end{Highlighting}
\end{Shaded}

\hypertarget{reverse-proxy-tls-example-caddy}{%
\subsubsection{4. Reverse Proxy TLS Example
(Caddy)}\label{reverse-proxy-tls-example-caddy}}

We strongly recommend placing \texttt{satspathd} behind a
TLS-terminating reverse proxy.

\textbf{Caddyfile example}:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{yourdomain.com \{}
\NormalTok{    reverse\_proxy localhost:4848}
\NormalTok{\}}
\end{Highlighting}
\end{Shaded}

\hypertarget{backup-restore}{%
\subsection{Backup \& Restore}\label{backup-restore}}

\begin{itemize}
\tightlist
\item
  \textbf{Backup}: Backup the \texttt{satspath-data} docker volume.
  Backups exclude user identity private keys because those keys never
  reside on the server.
\item
  \textbf{Restore}: Restoring a backup preserves the transparency
  \texttt{log\_id}, pins, histories, and witness continuity.
\end{itemize}

\hypertarget{upgrade-guidance}{%
\subsection{Upgrade Guidance}\label{upgrade-guidance}}

Upgrading \texttt{satspathd} is as simple as pulling the latest
container image and restarting:

\begin{Shaded}
\begin{Highlighting}[]
\ExtensionTok{docker{-}compose}\NormalTok{ pull}
\ExtensionTok{docker{-}compose}\NormalTok{ up }\AttributeTok{{-}d}
\end{Highlighting}
\end{Shaded}
