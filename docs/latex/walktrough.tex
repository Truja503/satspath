\hypertarget{what-satspath-is}{%
\subsection{What SatsPath Is}\label{what-satspath-is}}

SatsPath is a robust backend engine, protocol daemon
(\texttt{satspathd}), and CLI designed to act as a universal signed
payment resolver and router. It is intended to be embedded into existing
wallets (via WASM or FFI) or run as a standalone service, acting as the
``brain'' for resolving identity profiles and optimizing payment
routing.

It can:

\begin{itemize}
\tightlist
\item
  Resolve a local or peer-registered signed profile via multiple
  resolution methods (Local Registry, BIP-353 DNS, HTTP Well-Known,
  Nostr).
\item
  Select an optimal payment rail (Lightning, On-chain, Ark) based on
  live mempool fees and routing rules.
\item
  Authenticate and verify hybrid Post-Quantum signatures (ML-DSA-65 +
  Schnorr).
\item
  Fetch real LNURL invoices and BOLT12 offers.
\item
  Evaluate Silent Payments (BIP-352) and build BIP-21 on-chain URIs.
\item
  Preview swap directives (testnet only).
\end{itemize}

It cannot (and intentionally does not):

\begin{itemize}
\tightlist
\item
  Move funds automatically.
\item
  Sign Bitcoin transactions (no PSBT signing).
\item
  Broadcast anything to the network.
\item
  Store or generate seed phrases.
\item
  Execute mainnet swaps.
\end{itemize}

\hypertarget{architecture}{%
\subsection{Architecture}\label{architecture}}

The project has been pruned into a minimal, standalone backend ecosystem
focused purely on Rust (\texttt{crates/}), Cloudflare workers
(\texttt{proxy-workers/}), and integration SDKs.

\begin{itemize}
\tightlist
\item
  \textbf{\texttt{satspath-core}}: Core models, profile definition,
  identity keys (ECDSA/Schnorr/PQC), local registry, and resolvers
  (BIP-353, Nostr, HTTP).
\item
  \textbf{\texttt{satspath-router}}: The routing engine that queries
  live fees (with redundant oracles like mempool.space and
  mempool.ninja) and selects the best payment path.
\item
  \textbf{\texttt{satspath-pqc}}: Hybrid cryptographic suite combining
  classical signatures with ML-DSA-65.
\item
  \textbf{\texttt{satspathd}}: The standalone SatsPath daemon. It
  features zero-configuration authentication (auto-generating an
  \texttt{admin.macaroon} token) and a secure API middleware.
\item
  \textbf{\texttt{satspath-wasm}}: WASM bindings that allow embedding
  the SatsPath resolver and router into frontend applications.
\item
  \textbf{\texttt{satspath-cli}}: Command-line interface for
  human-readable interactions (ASCII QR codes, profile management, JSON
  quoting).
\item
  \textbf{\texttt{satspath-swaps}}: Experimental scaffold for Boltz
  Exchange v2 swap integration (testnet intent preview only).
\end{itemize}

\hypertarget{security-and-cryptography}{%
\subsection{Security and Cryptography}\label{security-and-cryptography}}

SatsPath is built with a strict Zero-Trust model:

\begin{itemize}
\tightlist
\item
  \textbf{Post-Quantum Cryptography (PQC):} Uses a hybrid signature
  scheme (\texttt{ML-DSA-65-Schnorr}) for generating and verifying
  identity keys. The engine validates that keys and signatures conform
  to these robust standards, while keeping execution times in the
  microsecond range.
\item
  \textbf{SSRF Protection:} Resolvers strictly validate URLs and block
  loopback, private, and internal metadata IP ranges (e.g.,
  \texttt{169.254.169.254}) to prevent malicious profile endpoints from
  exploiting internal networks.
\item
  \textbf{Nostr Concurrency \& Tombstoning:} Downloads profiles from
  multiple Nostr relays concurrently to ensure the most recent sequence
  is used, effectively preventing downgrade attacks. It strictly rejects
  revoked (tombstoned) profiles.
\item
  \textbf{Safe Persistence:} All local state (\texttt{.satspath/}) uses
  SHA-256 keyed storage. Sensitive swap material is stored using
  AES-256-GCM encryption, and plaintext writing is strictly guarded
  against.
\end{itemize}

\hypertarget{supported-payment-rails}{%
\subsection{Supported Payment Rails}\label{supported-payment-rails}}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Lightning Network:} Selected for smaller amounts (\textless{}
  100k sats). It handles LNURL-pay two-step fetches and parses BOLT11
  invoices to verify amounts.
\item
  \textbf{On-chain:} Selected for larger amounts when fees are
  acceptable. Includes support for Silent Payments (\texttt{sp1...}
  keys) which are seamlessly integrated into the generated
  \texttt{bitcoin:} URIs.
\item
  \textbf{Ark:} Fallback for when fees are high. Provides Ark payment
  pointers. (Client-side DAG validation is delegated to the integrating
  wallet).
\item
  \textbf{BOLT12:} An HTTP proxy scaffold
  (\texttt{proxy-workers/bolt12}) is available to resolve BOLT12 offers
  to real BOLT11 invoices asynchronously when native LNURL is
  unavailable.
\end{enumerate}
