\hypertarget{routing-model}{%
\section{Routing Model}\label{routing-model}}

SatsPath compares Lightning, on-chain Bitcoin, and Ark using public
profile data, fee estimates, and user preferences.

\texttt{RouteCandidate} includes:

\begin{itemize}
\tightlist
\item
  rail,
\item
  estimated fee,
\item
  estimated time,
\item
  privacy score,
\item
  reliability score,
\item
  user action requirement,
\item
  availability,
\item
  reason.
\end{itemize}

\hypertarget{mvp-rules}{%
\subsection{MVP Rules}\label{mvp-rules}}

Lightning:

\begin{itemize}
\tightlist
\item
  preferred for small and medium amounts when available,
\item
  uses conservative fee heuristics,
\item
  does not query private node data unless explicitly configured.
\end{itemize}

On-chain:

\begin{itemize}
\tightlist
\item
  estimates fee as vbytes multiplied by sat/vB,
\item
  rejects dust or economically irrational outputs,
\item
  preferred for large amounts or when Lightning is unavailable.
\end{itemize}

Ark:

\begin{itemize}
\tightlist
\item
  experimental,
\item
  considered when an Ark public pointer exists,
\item
  selected only when experimental Ark is allowed,
\item
  no mainnet settlement in SatsPath.
\end{itemize}

\hypertarget{execution-boundary}{%
\subsection{Execution Boundary}\label{execution-boundary}}

Route selection produces a payment pointer and explanation. It does not
sign, broadcast, settle, or move funds.
