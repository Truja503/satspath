\hypertarget{ark-routes}{%
\section{Ark Routes}\label{ark-routes}}

SatsPath treats Ark as a public payment rail and keeps execution
separate from route planning.

\hypertarget{direct-ark-receive}{%
\subsection{Direct Ark Receive}\label{direct-ark-receive}}

An Ark receiver can publish an Ark public pointer:

\begin{itemize}
\tightlist
\item
  Ark server URL,
\item
  compressed receiver public key,
\item
  optional VTXO pointer,
\item
  optional ownership proof.
\end{itemize}

If the sender is compatible with the same Ark server, the route planner
can produce an \texttt{ArkToArk} intent. This does not require Boltz,
Lightning, or an on-chain swap. Current SatsPath CLI output is
preview/intents unless explicitly testnet-executed and supported by the
local bridge.

\hypertarget{ark-swap-routes}{%
\subsection{Ark Swap Routes}\label{ark-swap-routes}}

Ark swaps are different from direct Ark receive:

\begin{itemize}
\tightlist
\item
  \texttt{ArkToLightning} requires an offboard/submarine-style path.
\item
  \texttt{LightningToArk} requires an onboard/reverse path.
\item
  \texttt{ArkToOnchain} requires Ark offboard support.
\item
  \texttt{OnchainToArk} requires Ark onboard support.
\end{itemize}

SatsPath does not call a normal Bitcoin address an Ark receive. If the
Ark bridge cannot create or claim the required Ark-side object, the
route is intent-only and fails closed for execution.

\hypertarget{current-status}{%
\subsection{Current Status}\label{current-status}}

\begin{itemize}
\tightlist
\item
  Ark route planning exists.
\item
  Ark direct receive/send previews exist.
\item
  Ownership proof verification exists.
\item
  Mainnet execution is disabled.
\item
  Testnet execution is gated by \texttt{-\/-testnet},
  \texttt{-\/-execute-testnet}, exact confirmation text, profile
  validation, Ark ownership proof validation, bridge availability,
  encrypted swap storage, and claim/refund builder availability.
\item
  Boltz Ark swap settlement is not implemented end to end.
\end{itemize}
