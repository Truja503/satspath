\hypertarget{identity-ownership-model}{%
\section{Identity Ownership Model}\label{identity-ownership-model}}

SatsPath maps human identifiers to signed public payment profiles. The
proof attached to an identifier depends on the identifier type.

\hypertarget{domain-owned-identifier}{%
\subsection{Domain-Owned Identifier}\label{domain-owned-identifier}}

Example:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{₿rodrigo@satspath.dev}
\end{Highlighting}
\end{Shaded}

A domain-owned identifier can be verified through DNS-based mechanisms
such as BIP-353 and DNSSEC when the domain owner publishes payment
instructions. This is the preferred protocol-native ownership model
because the user or wallet operator controls the domain namespace.

SatsPath must fail closed when DNSSEC validation is required but not
available. The current BIP-353 resolver is a scaffold and does not claim
full DNSSEC validation.

\hypertarget{platform-verified-email}{%
\subsection{Platform-Verified Email}\label{platform-verified-email}}

Example:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{rodrigo@gmail.com}
\end{Highlighting}
\end{Shaded}

For Gmail-style addresses, SatsPath cannot prove domain ownership
through DNS. A hosted SatsPath platform can only prove inbox access by
sending a code or magic link to that email address.

Email verification means:

\begin{itemize}
\tightlist
\item
  the receiver accessed the inbox,
\item
  the receiver can proceed to create or connect a wallet,
\item
  the receiver wallet can publish a signed public profile.
\end{itemize}

Email verification does not mean:

\begin{itemize}
\tightlist
\item
  SatsPath controls the domain,
\item
  SatsPath owns the wallet,
\item
  custody moved,
\item
  private keys or seed phrases were transferred.
\end{itemize}

\hypertarget{local-contact}{%
\subsection{Local Contact}\label{local-contact}}

A local contact is an alias stored on the local device. It is trusted
only by that local user/device. It is useful for demos, contacts, and
local registry fallbacks, but it is not global identity proof.

\hypertarget{privacy-note}{%
\subsection{Privacy Note}\label{privacy-note}}

Identifier hashes are used where possible, but hashed emails are not
strong anonymity because emails are guessable. Platform layers should
avoid storing raw emails except where delivery is required.
