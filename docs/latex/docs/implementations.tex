\hypertarget{satspath-implementations}{%
\section{SatsPath Implementations}\label{satspath-implementations}}

This document maps the SatsPath Protocol v1 specification to the current
repository implementation.

The implementation must be understood as a protocol stack, not as a
single P2P system. P2P is one transport implementation among several.

\hypertarget{signature-and-safety-validation}{%
\subsection{Signature and Safety
Validation}\label{signature-and-safety-validation}}

Implemented in:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{crates/satspath{-}core/src/crypto.rs}
\NormalTok{crates/satspath{-}core/src/validation.rs}
\end{Highlighting}
\end{Shaded}

Responsibilities:

\begin{itemize}
\tightlist
\item
  Generate protocol identity keypairs.
\item
  Sign public profiles.
\item
  Verify signed profiles.
\item
  Compute identity fingerprints.
\item
  Reject malformed public keys.
\item
  Reject private material in public protocol objects.
\item
  Validate Lightning addresses, Bitcoin addresses, Ark URLs, and
  compressed pubkeys.
\end{itemize}

Protocol identity keys are not wallet spending keys.

\hypertarget{p2p-transport-implementation}{%
\subsection{P2P Transport
Implementation}\label{p2p-transport-implementation}}

Implemented in:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{sdk/satspath{-}p2p/}
\end{Highlighting}
\end{Shaded}

This SDK is an optional transport. It publishes and resolves signed
profiles over Pear/Holepunch. It must be treated as a resolver
transport, not the whole protocol.

Conformance requirements:

\begin{itemize}
\tightlist
\item
  Return \texttt{SignedPaymentProfile} objects.
\item
  Verify before import or route use.
\item
  Never treat peer connectivity as profile ownership.
\item
  Never carry wallet private material.
\end{itemize}

Wire behavior is documented in \href{./wire_p2p.md}{wire\_p2p.md}.

\hypertarget{current-gaps}{%
\subsection{Current Gaps}\label{current-gaps}}

Known v1 implementation gaps:

\begin{itemize}
\tightlist
\item
  DNSSEC strict mode needs a local DNSSEC-validating resolver to fully
  trust BIP-353 on mainnet.
\item
  Nostr publishing is not yet exposed as a Rust CLI command; use a Nostr
  client to publish the kind 30078 event. Platform resolvers are
  scaffolds.
\item
  Resolver provenance is not yet carried through
  \texttt{ProfileResolver}, so signed-profile quote responses mark
  \texttt{identifier\_verified:\ false} unless a direct BIP-353 preview
  provides DNSSEC validation.
\item
  Mainnet payment execution is intentionally not implemented.
\item
  P2P wire envelopes should be formalized in the SDK to match
  \href{./wire_p2p.md}{wire\_p2p.md}.
\item
  Method ownership proofs exist in core but need broader resolver
  integration.
\end{itemize}

\hypertarget{conformance-checklist}{%
\subsection{Conformance Checklist}\label{conformance-checklist}}

An implementation in this repo should be considered conformant when it:

\begin{itemize}
\tightlist
\item
  Uses \texttt{SignedPaymentProfile} for receiver data.
\item
  Verifies signatures before routing.
\item
  Applies expiry checks.
\item
  Rejects unsafe private material.
\item
  Produces the four-status \texttt{QuoteResponse}.
\item
  Keeps resolver transports separate from protocol verification.
\item
  Treats Pear/Holepunch as optional transport.
\item
  Returns wallet handoff data instead of executing mainnet payments.
\end{itemize}
