\section{RFC-0046: SatsPath v2 - Authoritative Server-to-Server Identity
Resolution}\label{rfc-0046-satspath-v2---authoritative-server-to-server-identity-resolution}}

\hypertarget{objective}{%
\subsection{Objective}\label{objective}}

Move SatsPath from a transport-neutral/P2P-oriented prototype to an
\textbf{authoritative Server-to-Server (S2S) resolution protocol} for
identifiers such as \texttt{alice@example.com}.

A domain owner should be able to run a SatsPath authority for its own
namespace, publish a DNS-discoverable endpoint, and let wallets or other
SatsPath servers resolve proof-carrying payment profiles. A hosted
provider may also issue identifiers under its own domain.

\hypertarget{non-negotiable-security-invariant}{%
\subsection{Non-negotiable security
invariant}\label{non-negotiable-security-invariant}}

The server stores, logs, replicates, and serves identity data; it is
\textbf{not allowed to author identity changes}. A valid S2S response
must let a verifier establish all criteria without trusting the serving
server.
