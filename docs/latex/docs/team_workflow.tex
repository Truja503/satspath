\hypertarget{team-workflow-branch-discipline-and-pr-rules}{%
\section{Team Workflow, Branch Discipline, and PR
Rules}\label{team-workflow-branch-discipline-and-pr-rules}}

To maintain high code quality and prevent the team from breaking the
core routing engine or user experience, all contributors must adhere to
the following workflow.

\hypertarget{branching-strategy}{%
\subsection{1. Branching Strategy}\label{branching-strategy}}

\begin{itemize}
\tightlist
\item
  \textbf{No direct commits to \texttt{main}.}
\item
  \texttt{main} must ALWAYS run the SatsPath demo flawlessly.
\item
  All new work must be done on feature branches.
\item
  Feature branches are merged into \texttt{develop} or experimental
  integration branches first.
\item
  \texttt{develop} is merged into \texttt{main} ONLY when the demo is
  fully tested and verified.
\end{itemize}

\textbf{Branch Naming Convention:}

\begin{itemize}
\tightlist
\item
  \texttt{feature/\textless{}issue-name\textgreater{}} (e.g.,
  \texttt{feature/lnurl-pay})
\item
  \texttt{fix/\textless{}issue-name\textgreater{}} (e.g.,
  \texttt{fix/dust-threshold})
\item
  \texttt{docs/\textless{}issue-name\textgreater{}}
\end{itemize}

\hypertarget{pull-request-pr-rules}{%
\subsection{2. Pull Request (PR) Rules}\label{pull-request-pr-rules}}

\begin{itemize}
\tightlist
\item
  \textbf{One issue = one branch = one PR.} Keep scope tight.
\item
  Do not mix protocol changes, frontend changes, and execution logic in
  the same PR.
\item
  \textbf{No secrets in commits.} Never commit private keys, macaroons,
  or .env files.
\item
  Mainnet execution code requires a mandatory Security Review before
  merging.
\end{itemize}

\hypertarget{pr-checklist}{%
\subsubsection{PR Checklist}\label{pr-checklist}}

Before requesting a review, the author must ensure:

\begin{itemize}
\tightlist
\item[$\square$]
  Code compiles and tests pass (\texttt{cargo\ test\ -\/-workspace}).
\item[$\square$]
  The existing demo still works.
\item[$\square$]
  New components do not introduce dangerous mainnet fallbacks.
\item[$\square$]
  No fake invoices or plaintext secret storage were added.
\end{itemize}

\hypertarget{definition-of-done}{%
\subsection{3. Definition of Done}\label{definition-of-done}}

A task is considered ``Done'' when:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  The acceptance criteria in the issue are fully met.
\item
  Unit tests or integration mocks cover the success and failure paths.
\item
  The PR is reviewed and approved by the respective module owner (e.g.,
  Swap engine owner, Protocol Rust owner).
\item
  The code is merged into the target branch without breaking existing
  pipelines.
\end{enumerate}
