\hypertarget{executive-summary-non-negotiable-invariants}{%
\subsection{1. Executive Summary \& Non-Negotiable
Invariants}\label{executive-summary-non-negotiable-invariants}}

In SatsPath v2, resolution moves from unauthenticated transport/P2P
mechanisms to an \textbf{authoritative, proof-carrying Server-to-Server
(S2S) resolution protocol}.

\hypertarget{core-invariant}{%
\subsubsection{Core Invariant}\label{core-invariant}}

\begin{quote}
\textbf{The server stores, logs, replicates, and serves identity data;
it is \emph{strictly forbidden from authoring identity changes}.}
\end{quote}

A self-signed profile alone is insufficient: a malicious or compromised
registry could substitute both the identity key and profile while
returning a self-consistent cryptographic signature. Similarly, a Merkle
tree proof alone is insufficient if an adversarial server can construct
bifurcated trees (split-view attacks) for different verifiers.

SatsPath v2 decouples \textbf{Integrity}, \textbf{Freshness},
\textbf{Global Consistency}, \textbf{Namespace Authority},
\textbf{Payment-Method Ownership}, and \textbf{Availability}. A binary
\texttt{verified:\ true} flag is explicitly prohibited.

\hypertarget{domain-sovereign}{%
\subsubsection{1. Domain-Sovereign}\label{domain-sovereign}}

\begin{itemize}
\tightlist
\item
  \textbf{Description}: The user or entity owns the domain name
  (\texttt{example.com}) and publishes DNSSEC-signed \texttt{\_satspath}
  delegation records pointing to their authoritative log.
\item
  \textbf{Trust Anchor}: Root DNSSEC trust anchor (\texttt{.})
  \(\rightarrow\) Domain KSK/ZSK \(\rightarrow\)
  \texttt{NamespaceDescriptor}.
\item
  \textbf{Security Properties}: Protected against network MITM, DNS
  spoofing, and BGP hijacks. Full self-sovereignty.
\end{itemize}

\hypertarget{domain-webpki}{%
\subsubsection{2. Domain / WebPKI}\label{domain-webpki}}

\begin{itemize}
\tightlist
\item
  \textbf{Description}: Domain authority is discovered over HTTPS
  (\texttt{https://example.com/.well-known/satspath-authority}), but
  DNSSEC is absent or unvalidated.
\item
  \textbf{Trust Anchor}: Public WebPKI CA hierarchy.
\item
  \textbf{Security Properties}: Vulnerable to rogue CA issuance or DNS
  hijacking, but protected against passive eavesdropping and
  retrospective log tampering via witness signatures.
\end{itemize}

\hypertarget{hosted-identifier}{%
\subsubsection{3. Hosted Identifier}\label{hosted-identifier}}

\begin{itemize}
\tightlist
\item
  \textbf{Description}: The user has an identifier under a third-party
  domain (e.g., \texttt{alice@fiatjaf.com} or \texttt{bob@strike.me}).
\item
  \textbf{Trust Anchor}: The hosting provider's namespace descriptor and
  log operator key.
\item
  \textbf{Security Properties}: Provider can censor the user or refuse
  to log new updates, but \emph{cannot} forge signatures on behalf of
  the user's existing identity key without cryptographic verification
  failure. \textbf{UI MUST clearly flag this as Hosted and NOT
  Domain-Sovereign.}
\end{itemize}

\hypertarget{explicit-pin-tofu-trust-on-first-use}{%
\subsubsection{4. Explicit Pin / TOFU
(Trust-On-First-Use)}\label{explicit-pin-tofu-trust-on-first-use}}

\begin{itemize}
\tightlist
\item
  \textbf{Description}: Verifier establishes a local pin on first
  contact (\texttt{NamespaceDescriptorHash} + \texttt{LogId} +
  \texttt{RootHash}) and requires monotonic append-only continuity for
  all future resolutions.
\item
  \textbf{Trust Anchor}: First verified checkpoint stored locally.
\item
  \textbf{Security Properties}: Detects any subsequent unauthorized
  operator key swap, log fork, or namespace redirection.
\end{itemize}

\hypertarget{explicitly-out-of-scope-for-v2}{%
\subsection{6. Explicitly Out of Scope for
v2}\label{explicitly-out-of-scope-for-v2}}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Custodial Funds Handling}: SatsPath does not hold, escrow,
  lock, or transfer Bitcoin or fiat funds.
\item
  \textbf{Forced Server Availability}: Cryptography proves correctness
  and detects equivocation, but cannot force an unresponsive server to
  reply.
\item
  \textbf{Email Inbox Proof}: Ownership of \texttt{user@domain.com} in
  SatsPath represents routing authority within the SatsPath namespace,
  not proof of SMTP/IMAP mailbox possession.
\item
  \textbf{Arbitrary Social Recovery}: No social or back-door recovery
  without pre-committed on-chain / cryptographic threshold scripts.
\end{enumerate}
