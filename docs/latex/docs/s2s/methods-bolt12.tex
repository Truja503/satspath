\hypertarget{bolt12-offers-in-satspath}{%
\section{BOLT12 Offers in SatsPath}\label{bolt12-offers-in-satspath}}

SatsPath supports BOLT12 offers as a first-class, identity-bound payment
method. This allows users to publish reusable payment instructions while
ensuring SatsPath remains strictly a discovery and routing layer rather
than executing payments itself.

\hypertarget{data-model}{%
\subsection{Data Model}\label{data-model}}

The \texttt{PaymentMethod} enum includes the
\texttt{Bolt12(Bolt12Offer)} variant:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{\{}
  \DataTypeTok{"type"}\FunctionTok{:} \StringTok{"Bolt12"}\FunctionTok{,}
  \DataTypeTok{"label"}\FunctionTok{:} \StringTok{"Donation Offer"}\FunctionTok{,}
  \DataTypeTok{"offer"}\FunctionTok{:} \StringTok{"lno1..."}\FunctionTok{,}
  \DataTypeTok{"network"}\FunctionTok{:} \StringTok{"mainnet"}\FunctionTok{,}
  \DataTypeTok{"issuer\_pubkey"}\FunctionTok{:} \StringTok{"03..."}
\FunctionTok{\}}
\end{Highlighting}
\end{Shaded}

The exact BOLT12 string (\texttt{lno1...}) is preserved and signed
directly within the user's profile.

\hypertarget{validation-parsing}{%
\subsection{Validation \& Parsing}\label{validation-parsing}}

SatsPath strictly validates offers before allowing them into the
profile:

\begin{itemize}
\tightlist
\item
  \textbf{Prefix validation}: \texttt{lno} for mainnet, \texttt{lnot}
  for testnet.
\item
  \textbf{Length checks}: Ensures the bech32 payload isn't prematurely
  truncated or synthetic.
\item
  \textbf{Network enforcement}: The expected network must match the
  prefix.
\end{itemize}

\emph{Future extensions will decode full TLV trees to validate expiry,
unknown required feature bits, and amount constraints directly.}

\hypertarget{routing-handoff}{%
\subsection{Routing \& Handoff}\label{routing-handoff}}

When resolving a SatsPath identifier that prefers BOLT12, the server
returns the raw offer payload to the client. The client/wallet then
decides whether to:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Parse the BOLT12 offer directly.
\item
  Rely on a \texttt{bitcoin:?lno=...} (BIP-321) URI handoff to trigger a
  standard wallet payment flow.
\end{enumerate}

SatsPath servers \textbf{never} attempt to fetch an invoice
(e.g.~\texttt{invoice\_request}) on behalf of the user, preserving the
privacy and non-custodial nature of the S2S routing layer.
