\hypertarget{satspath-v2-server-migration-identifier-portability}{%
\section{SatsPath v2 Server Migration \& Identifier
Portability}\label{satspath-v2-server-migration-identifier-portability}}

\hypertarget{overview}{%
\subsection{Overview}\label{overview}}

A domain owner must be able to move from one SatsPath server to another
while keeping \texttt{user@domain}, owner keys, histories, and verifier
trust intact. Endpoint ownership and identity ownership are strictly
decoupled.

\hypertarget{identity-layers}{%
\subsection{Identity Layers}\label{identity-layers}}

\hypertarget{migration-cases}{%
\subsection{Migration Cases}\label{migration-cases}}

\hypertarget{planned-move-old-server-cooperating}{%
\subsubsection{1. Planned Move (Old Server
Cooperating)}\label{planned-move-old-server-cooperating}}

The old server exports a signed \texttt{MigrationStatement} binding its
latest checkpoint to the new endpoint. The new server imports the full
event stream, verifies it, and begins serving.

\hypertarget{old-server-offline-censoring}{%
\subsubsection{2. Old Server Offline /
Censoring}\label{old-server-offline-censoring}}

If the domain owner holds the namespace authority key, they can issue a
new \texttt{NamespaceDescriptor} pointing to the new endpoint. Clients
with pinned checkpoints verify continuation via consistency proofs from
the new server.

\hypertarget{operator-key-compromise}{%
\subsubsection{3. Operator Key
Compromise}\label{operator-key-compromise}}

The namespace authority issues an \texttt{OperatorKeyRotation} and a new
descriptor epoch. The old operator key is revoked.

\hypertarget{witness-set-change}{%
\subsubsection{4. Witness Set Change}\label{witness-set-change}}

A new descriptor epoch lists updated witness pubkeys and quorum
requirements.

\hypertarget{replica-promotion}{%
\subsubsection{5. Replica Promotion}\label{replica-promotion}}

A healthy replica is promoted by updating DNS and issuing a migration
statement.

\hypertarget{hosted-user-moving-to-new-domain}{%
\subsubsection{6. Hosted User Moving to New
Domain}\label{hosted-user-moving-to-new-domain}}

A provider-owned domain cannot be unilaterally redirected. Instead, a
signed redirect links the old \texttt{alice@provider.example} to a new
sovereign identifier \texttt{alice@sovereign.example}. Clients display
this as a \textbf{new identifier}, not a transparent migration.

\hypertarget{export-import-format}{%
\subsection{Export / Import Format}\label{export-import-format}}

A portable \texttt{MigrationExport} contains: - Signed
\texttt{NamespaceDescriptor} (current epoch) - Full signed event stream
(\texttt{Vec\textless{}NameEvent\textgreater{}}) - All checkpoints with
operator signatures - Consistency proofs bridging checkpoints -
Current-state map reconstruction data - Witness cosignature receipts -
Operator key transition history

Exports contain \textbf{no identity private keys} unless a separate
local client backup action handles them explicitly.

\hypertarget{security-properties}{%
\subsection{Security Properties}\label{security-properties}}

\begin{itemize}
\tightlist
\item
  A malicious old or new server cannot fabricate a migration.
\item
  DNS rollback and endpoint rollback are detected and rejected.
\item
  Clients with an old valid descriptor receive a precise
  \texttt{migration\_required} or \texttt{policy\_changed} result.
\item
  The new server reconstructs and verifies the full state before
  advertising readiness.
\end{itemize}
