\section{SatsPath v2 Authoritative
Server}\label{satspath-v2-authoritative-server}}

\hypertarget{overview}{%
\subsection{Overview}\label{overview}}

The SatsPath v2 server is an authoritative, network-facing identity
resolution service that hosts one or more namespaces and returns fully
proof-carrying resolution envelopes. It is strictly a discovery layer:
it does not sign or broadcast payments and accepts no wallet spending
secrets.

\hypertarget{v2-api-endpoints}{%
\subsection{V2 API Endpoints}\label{v2-api-endpoints}}

\hypertarget{get-v2namespace}{%
\subsubsection{\texorpdfstring{\texttt{GET\ /v2/namespace}}{GET /v2/namespace}}\label{get-v2namespace}}

Returns the signed \texttt{NamespaceDescriptor} for the hosted domain,
including the operator public key, witness quorum policy, and endpoint
list.

\hypertarget{get-v2resolveidentifier}{%
\subsubsection{\texorpdfstring{\texttt{GET\ /v2/resolve/:identifier}}{GET /v2/resolve/:identifier}}\label{get-v2resolveidentifier}}

Returns a complete \texttt{ResolutionEnvelope} containing: - The signed
payment profile. - All name events for the identifier. - Merkle
inclusion proof binding the event to the log. - Consistency proof (if
the client provides a pinned tree size). - Current-state map proof
(inclusion or non-inclusion). - Witness cosignatures meeting the quorum
threshold. - The latest signed checkpoint.

\hypertarget{get-v2checkpointlatest}{%
\subsubsection{\texorpdfstring{\texttt{GET\ /v2/checkpoint/latest}}{GET /v2/checkpoint/latest}}\label{get-v2checkpointlatest}}

Returns the latest signed \texttt{TransparencyCheckpoint} with its
witness cosignatures.

\hypertarget{get-v2health}{%
\subsubsection{\texorpdfstring{\texttt{GET\ /v2/health}}{GET /v2/health}}\label{get-v2health}}

Returns readiness status, version, checkpoint age, witness quorum
health, and replica lag metrics.

\hypertarget{resolution-pipeline}{%
\subsection{Resolution Pipeline}\label{resolution-pipeline}}

\begin{verbatim}
canonical identifier
-> discover authoritative namespace
-> fetch proof envelope
-> verify namespace binding
-> verify owner event/profile
-> verify current-state proof
-> verify append-only inclusion + consistency
-> verify operator continuity + witness policy
-> verify method ownership
-> route
\end{verbatim}

Every quote/pay/preview path must consume the same verified result.
Legacy data or transport responses must not bypass this composition.

\hypertarget{security-requirements}{%
\subsection{Security Requirements}\label{security-requirements}}

\begin{itemize}
\tightlist
\item
  HTTPS required in deployment; strict origin/redirect rules in the
  client.
\item
  Atomic SQLite persistence remains fail-closed under crashes.
\item
  Bounded request/response bodies, proof depths, histories, concurrency,
  and timeouts.
\item
  Rate limits per namespace/IP without changing cryptographic truth.
\item
  SSRF prevention through descriptors, payment-method metadata,
  redirects, and replica URLs.
\item
  No logging of auth tokens, challenges, full sensitive request
  metadata, or any private keys.
\item
  Multi-tenant namespace separation prevents cross-namespace reads,
  writes, proof reuse, and key confusion.
\end{itemize}
