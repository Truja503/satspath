\hypertarget{satspath-v2-name-events}{%
\section{SatsPath v2 Name Events}\label{satspath-v2-name-events}}

\hypertarget{goal}{%
\subsection{Goal}\label{goal}}

Make the authoritative server an admission and storage service, never
the author of identity state. Every accepted mutation must be
independently verifiable from the signed event history.

\hypertarget{event-model}{%
\subsection{Event Model}\label{event-model}}

Canonical events for the lifecycle of a namespace identifier: -
\texttt{Register} - \texttt{ProfileUpdate} - \texttt{RotateOwnerKey} -
\texttt{Revoke} - \texttt{RecoverKey} (optional, disabled by default)

Every event MUST bind: - \texttt{identifier\_hash} - Namespace
identifier - \texttt{action} (event type) - \texttt{sequence} -
\texttt{previous\_event\_hash} - \texttt{profile\_hash} - policy epoch -
validity/freshness fields (\texttt{created\_at})

\hypertarget{authorization-rules}{%
\subsection{Authorization Rules}\label{authorization-rules}}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Registration}: Requires namespace issuance authorization plus
  proof that the proposed owner key accepts the binding (sequence 0, no
  previous event hash).
\item
  \textbf{Profile Updates}: Requires the signature of the current owner
  key.
\item
  \textbf{Key Rotation}: Requires authorization by the old key and
  acceptance by the new key.
\item
  \textbf{Revocation}: Requires the current owner key. This is a
  terminal state.
\item
  \textbf{Continuous Sequence}: Sequence must advance by exactly one.
\item
  \textbf{Chaining}: \texttt{previous\_event\_hash} must match the
  cryptographic hash of the current state.
\item
  \textbf{Compare-and-set}: Concurrent mutations use compare-and-set
  semantics; only one successor to a history head can commit.
\item
  \textbf{No Server Forgery}: A server must reject a syntactically valid
  self-signed replacement key that lacks history continuity.
\end{enumerate}

\hypertarget{namespace-policy}{%
\subsection{Namespace Policy}\label{namespace-policy}}

Namespaces control admission, reserved names, and expiration, but they
do NOT gain the ability to forge owner updates. Policy changes must be
versioned and cannot retroactively weaken already-issued identifiers.
