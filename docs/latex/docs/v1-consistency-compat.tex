\section{Consistency Proofs: Wire Formats and Backward Compatibility
Policy}\label{consistency-proofs-wire-formats-and-backward-compatibility-policy}}

\hypertarget{overview}{%
\subsection{Overview}\label{overview}}

Transparency logs prove that the log is append-only through
\textbf{Merkle consistency proofs}. When a client pins a checkpoint at
tree size \(m\) with root \(R_m\) and later receives a checkpoint at
tree size \(n\) (\(n \ge m\)) with root \(R_n\), a consistency proof
demonstrates that the first \(m\) leaves of the new tree match the
original \(m\) leaves, without requiring the client to download the full
log.

SatsPath supports two versions of the consistency proof wire format:

\hypertarget{fields}{%
\subsubsection{Fields}\label{fields}}

\begin{itemize}
\tightlist
\item
  \texttt{version} (\texttt{u16}): Proof format version (\texttt{1} or
  \texttt{2}).
\item
  \texttt{old\_tree\_size} (\texttt{u64}): Tree size \(m\) at the prior
  pinned checkpoint (\(m > 0\)).
\item
  \texttt{new\_tree\_size} (\texttt{u64}): Tree size \(n\) at the new
  checkpoint (\(n \ge m\)).
\item
  \texttt{old\_root} (\texttt{String}, hex): Expected root hash at size
  \(m\).
\item
  \texttt{new\_root} (\texttt{String}, hex): Expected root hash at size
  \(n\).
\item
  \texttt{audit\_path} (\texttt{Vec\textless{}String\textgreater{}},
  hex):

  \begin{itemize}
  \tightlist
  \item
    In \textbf{V1}: Contains all \(n\) leaf hashes of the new tree.
  \item
    In \textbf{V2}: Contains the \(O(\log n)\) intermediate
    sibling/subtree node hashes specified by RFC 6962.
  \end{itemize}
\end{itemize}

\hypertarget{backward-compatibility-policy}{%
\subsection{Backward Compatibility
Policy}\label{backward-compatibility-policy}}

\hypertarget{proof-generation-transparencylogconsistency}{%
\subsubsection{\texorpdfstring{1. Proof Generation
(\texttt{TransparencyLog::consistency})}{1. Proof Generation (TransparencyLog::consistency)}}\label{proof-generation-transparencylogconsistency}}

\begin{itemize}
\tightlist
\item
  All new consistency proofs produced by
  \texttt{TransparencyLog::consistency(old\_size,\ new\_size)} are
  emitted using \textbf{Version 2 (RFC 6962 compact)}.
\item
  Tree size is bounded only by the actual log size; no arbitrary 16,384
  leaf ceiling is applied to V2 generation.
\end{itemize}

\hypertarget{verifier-support-verify_consistency_proof}{%
\subsubsection{\texorpdfstring{2. Verifier Support
(\texttt{verify\_consistency\_proof})}{2. Verifier Support (verify\_consistency\_proof)}}\label{verifier-support-verify_consistency_proof}}

\begin{itemize}
\tightlist
\item
  \textbf{Version 2 proofs (RFC 6962)}:

  \begin{itemize}
  \tightlist
  \item
    Verified according to RFC 6962 consistency proof arithmetic.
  \item
    Verification operates in \(O(\log n)\) time and \(O(1)\) auxiliary
    memory per step.
  \item
    Pure verification: Does not trust the server or log operator.
  \item
    Bit-flips, truncated paths, reordered paths, or tampered roots fail
    closed.
  \end{itemize}
\item
  \textbf{Version 1 proofs (Bounded Legacy)}:

  \begin{itemize}
  \tightlist
  \item
    Verifier checks that \texttt{new\_tree\_size\ \textless{}=\ 16,384}.
  \item
    Verifier validates that
    \texttt{audit\_path.len()\ ==\ new\_tree\_size}.
  \item
    Recomputes
    \texttt{merkle\_root(\&audit\_path{[}..old\_tree\_size{]})\ ==\ old\_root}
    and \texttt{merkle\_root(\&audit\_path)\ ==\ new\_root}.
  \item
    Any V1 proof with \texttt{new\_tree\_size\ \textgreater{}\ 16,384}
    is \textbf{rejected immediately} prior to slicing or allocating
    memory, preserving DDoS resistance against malformed V1 payloads.
  \end{itemize}
\end{itemize}

\hypertarget{checkpoint-binding-and-local-pinning}{%
\subsubsection{3. Checkpoint Binding and Local
Pinning}\label{checkpoint-binding-and-local-pinning}}

\begin{itemize}
\tightlist
\item
  Consistency proof verification remains strictly bound to signed
  checkpoints and local pinned state.
\item
  Transition checks (\texttt{verify\_checkpoint\_transition}) ensure:

  \begin{itemize}
  \tightlist
  \item
    \texttt{old\_tree\_size} matches the locally pinned checkpoint tree
    size.
  \item
    \texttt{new\_tree\_size} matches the candidate checkpoint tree size.
  \item
    \texttt{old\_root} matches the locally pinned checkpoint root.
  \item
    \texttt{new\_root} matches the candidate checkpoint root.
  \item
    Operator key continuity and sequence numbers are preserved.
  \end{itemize}
\end{itemize}
