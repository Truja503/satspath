\hypertarget{mainnet-safety-security-guidelines}{%
\section{Mainnet Safety \& Security
Guidelines}\label{mainnet-safety-security-guidelines}}

SatsPath is a powerful routing engine that coordinates interactions
across multiple Bitcoin layers (Lightning, On-chain, and Ark). Moving
real funds on Mainnet carries inherent risks. This document establishes
the security perimeter for the engine.

\hypertarget{non-custodial-architecture}{%
\subsection{1. Non-Custodial
Architecture}\label{non-custodial-architecture}}

\textbf{SatsPath is NOT a custodial wallet.}

\begin{itemize}
\tightlist
\item
  The \texttt{Identity\ Key} (used to sign profiles) \textbf{does not}
  control funds.
\item
  Wallet, Node, or SDK plugins are responsible for securely managing
  funds and signing transactions.
\item
  Never store seed phrases, wallet private keys, macaroons, certs, API
  tokens, or other high-value secrets in the SatsPath repository or
  plaintext config files.
\item
  Email verification proves inbox access only. It does not transfer
  custody and does not prove ownership of a Gmail-style domain.
\item
  Receiver wallets must generate private keys locally on the receiver's
  device and publish only public payment profiles.
\end{itemize}

\hypertarget{mainnet-preview-vs-mainnet-execution}{%
\subsection{2. Mainnet Preview vs Mainnet
Execution}\label{mainnet-preview-vs-mainnet-execution}}

\hypertarget{mainnet-preview}{%
\subsubsection{Mainnet Preview}\label{mainnet-preview}}

Mainnet Preview is allowed because it touches public data only:

\begin{itemize}
\tightlist
\item
  signed public payment profiles,
\item
  public identity keys,
\item
  public Lightning Address / LNURL metadata,
\item
  BOLT11 invoice strings when explicitly requested,
\item
  public on-chain addresses,
\item
  BIP21 \texttt{bitcoin:} URIs,
\item
  public Ark server and receiver pubkey pointers,
\item
  route quotes and fee estimates,
\item
  QR/payment pointer display.
\end{itemize}

Mainnet Preview does not move funds. It does not sign transactions,
broadcast transactions, execute swaps, create/send Ark VTXOs,
offboard/onboard, or touch wallet private keys.

\hypertarget{mainnet-execution}{%
\subsubsection{Mainnet Execution}\label{mainnet-execution}}

Mainnet execution is not implemented. No CLI flag exists for it. Any
future mainnet execution feature must be a separate audited change with
stronger confirmation gates and secret-storage controls.

The safe commands are preview commands:

\hypertarget{mainnet-configuration}{%
\subsection{3. Mainnet Configuration}\label{mainnet-configuration}}

By default, the SatsPath Swap Engine operates in \textbf{Testnet mode}.

\textbf{Required Safety Defaults:}

\begin{itemize}
\tightlist
\item
  \texttt{mainnet\_enabled\ =\ false}
\item
  \texttt{max\_mainnet\_payment\_sats\ =\ 1000}
\item
  \texttt{require\_manual\_confirmation\ =\ true}
\item
  \texttt{fail\_closed\ =\ true}
\end{itemize}

Mainnet preview is allowed because it touches public data only. Mainnet
execution is disabled. \texttt{-\/-experimental-swaps\ -\/-testnet} is
for testnet-only engine scaffolding; mainnet execution requires a
separate future feature with stronger confirmation gates.

\hypertarget{strict-pre-execution-checks}{%
\subsection{4. Strict Pre-Execution
Checks}\label{strict-pre-execution-checks}}

Before executing \emph{any} Mainnet transaction or Swap, the engine MUST
abort if any of the following checks fail:

\begin{itemize}
\tightlist
\item
  \textbf{Amount Mismatch:} Abort if the requested invoice amount does
  not match the BOLT11 invoice returned by LNURL or Boltz.
\item
  \textbf{Signature Verification:} Abort if the
  \texttt{SignedPaymentProfile} signature is invalid or tampered with.
\item
  \textbf{Metadata Invalid:} Abort if LNURL metadata violates expected
  tags or amount bounds.
\item
  \textbf{Expiration:} Abort if the payment profile has expired.
\end{itemize}

\hypertarget{first-mainnet-tests}{%
\subsection{5. First Mainnet Tests}\label{first-mainnet-tests}}

When testing features on Mainnet for the first time:

\begin{itemize}
\tightlist
\item
  Use tiny amounts only (e.g., \texttt{\textless{}\ 1000\ sats}).
\item
  Verify routing paths locally before broadcasting.
\item
  Ensure that the local \texttt{.satspath/swaps.enc} vault is encrypting
  secrets via AES-GCM and not falling back silently to plaintext.
\end{itemize}

\hypertarget{bip-353-dns-resolution-mainnet-preview}{%
\subsection{5. BIP-353 DNS Resolution (Mainnet
Preview)}\label{bip-353-dns-resolution-mainnet-preview}}

BIP-353 resolution is a \textbf{preview} layer: SatsPath resolves and
displays DNSSEC-backed payment instructions but never pays, signs, or
broadcasts.

\begin{itemize}
\tightlist
\item
  \textbf{DNSSEC is mandatory.} The default \texttt{Strict} policy fails
  closed and does not trust an upstream resolver's AD bit.
  \texttt{DevInsecure} mode is local-testing only, requires
  \texttt{-\/-allow-insecure-dns-for-dev}, and prints a loud warning.
\item
  \textbf{Ambiguity is invalid.} More than one \texttt{bitcoin:} TXT
  record at a name, or an unknown \texttt{req-*} parameter, makes
  resolution fail.
\item
  \textbf{No private material} may ever appear in a published or
  resolved DNS payload (\texttt{seed}, \texttt{xprv}/\texttt{tprv},
  \texttt{mnemonic}, \texttt{macaroon}, \texttt{cert},
  \texttt{api\_key}, \texttt{claim\_key}, \texttt{refund\_key},
  \texttt{preimage}, \ldots) --- screened on both publish and resolve.
\item
  \textbf{Record changes require an identity-key signature.} Email
  access alone never authorizes a DNS payment-instruction change.
\item
  \textbf{Consumer email domains} (e.g.~\texttt{gmail.com}) cannot use
  BIP-353; they fall back to platform verification / the invite flow.
\item
  \textbf{DNS-provider credentials are never committed} --- only a trait
  + mock publisher ship in this repo.
\end{itemize}
