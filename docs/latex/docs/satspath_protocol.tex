\hypertarget{satspath-protocol}{%
\section{SatsPath Protocol}\label{satspath-protocol}}

SatsPath is an open Bitcoin payment resolver and routing protocol.
Wallets can implement it without using a SatsPath-hosted platform.

The protocol flow is:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{identifier {-}\textgreater{} signed public profile {-}\textgreater{} public payment pointers {-}\textgreater{} route decision {-}\textgreater{} QR/payment intent}
\end{Highlighting}
\end{Shaded}

\hypertarget{public-profile}{%
\subsection{Public Profile}\label{public-profile}}

A \texttt{PaymentProfile} contains public information only:

\begin{itemize}
\tightlist
\item
  identifier alias,
\item
  identity public key,
\item
  Lightning Address, LNURL, or BOLT-style public invoice data,
\item
  on-chain public addresses and public descriptor hints,
\item
  Ark server and receiver public key,
\item
  update and expiry timestamps.
\end{itemize}

The profile is signed by the user's identity key. That identity key does
not control funds by itself. Wallets and nodes control funds.

\hypertarget{payment-pointers}{%
\subsection{Payment Pointers}\label{payment-pointers}}

\texttt{PaymentPointer} is the stable output from resolution/routing. It
may contain:

\begin{itemize}
\tightlist
\item
  Lightning Address,
\item
  LNURL-pay callback,
\item
  BOLT11 invoice as data,
\item
  Bitcoin address with public claim policy metadata,
\item
  Ark public pointer.
\end{itemize}

It must never contain private keys, seed phrases, macaroons,
certificates, API secrets, or signing keys.

\hypertarget{mainnet-preview-vs-mainnet-execution}{%
\subsection{Mainnet Preview vs Mainnet
Execution}\label{mainnet-preview-vs-mainnet-execution}}

Mainnet Preview is supported as a safe public-data mode. A wallet or app
can ask SatsPath to resolve a recipient, verify the signed profile,
choose a rail, and return a mainnet-compatible payment pointer or QR
payload.

Mainnet Preview may return public instructions such as Lightning Address
pointers, explicitly requested BOLT11 invoices as data, BIP21
\texttt{bitcoin:} URIs, or Ark \texttt{satspath:ark} intent URIs. The
caller must use its own wallet to pay.

Mainnet Execution is not implemented. SatsPath does not custody funds,
does not sign Bitcoin transactions, does not broadcast transactions, and
does not store wallet private keys.

\hypertarget{platform}{%
\subsection{Platform}\label{platform}}

The SatsPath Platform is optional. It can provide:

\begin{itemize}
\tightlist
\item
  email verification for normal users,
\item
  invite links,
\item
  API-based profile publishing,
\item
  public profile lookup.
\end{itemize}

It must never custody funds and must never see wallet private keys.

\hypertarget{compatibility}{%
\subsection{Compatibility}\label{compatibility}}

BIP-353 discovers payment instructions through DNS. BIP-321/BIP-21 style
\texttt{bitcoin:} URIs encode payment instructions. SatsPath extends
this by adding signed public profiles and route selection across
Lightning, on-chain Bitcoin, and Ark.
